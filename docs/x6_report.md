# X6: hijack containment, detection and recovery

Phase 2 assumes the agent is already hijacked: the leaked key submits straight to the bundler, so the wallet's own validation, sandbox and detectors are what get tested (the tools' pre-check is deliberately bypassed). Generated by `tools/render_reports.py` from the results files; every number carries its source marker and `python tools/check_claims.py` rebuilds each one.

## Protocol

Pre-registered in `nikunj/EXPERIMENTS.md` (X6). Thresholds were fixed on dev seeds 1-3 (rule written before the sweep ran, see below) and pinned in `agent/hijack/thresholds.json` before any scored seed ran. Scored seeds 42 [r:results/x6_detection.json#meta.seeds.0] to 61 [r:results/x6_detection.json#meta.seeds.19], one fresh anvil chain per run, so a seed reproduces a run exactly (amounts, counts, gaps and payees come from a seeded rng). Nine hijack scenarios and four legit workloads, each run in four detector modes: combined (tripwires + watcher), tripwires only (on-chain), watcher only (off-chain), no detector (caps only). Records written: 1,040 [r:results/x6_detection.json#meta.totalRecords], of which pending or errored: 0 [r:results/x6_detection.json#meta.pendingOrError]. Nothing was dropped or re-run selectively.

Metric definitions:

- **Detection rate** = hijack runs frozen before the run ends / hijack runs that reached the wallet (an op was mined, or the attack has an off-chain signal). H4, H5 and H7 are stopped at doors a chain-based detector never sees (a token-side signature, an op rejected in validation, a guardian quorum that cannot form), so they are contained but outside the detection denominator.
- **Containment rate** = hijack runs whose loss stayed inside the stated bound / all hijack runs. Bound: the daily limit (global cap), the exploration cap for unproven payees, and each scenario's own bound (paymaster quota, recovery).
- **False-freeze rate** = legit runs with at least one freeze / legit runs. Legit workloads go through the tools like an honest agent.
- CI = Wilson 95% interval; the cells are small, so a point estimate alone would overstate precision.

## What the numbers show

- **Containment does not depend on detection.** With every detector off the loss bound still holds in every run; the buckets and the exploration cap are the containment, the detectors shorten the attack.
- **The only missed detections are the threshold-aware slow drain (H2).** It is paced to stay under the velocity tripwire and the CUSUM drift; it is detected in 16 [r:results/x6_detection.json#byMode.combined.detectionByScenario.H2.detection.hit] of 20 [r:results/x6_detection.json#byMode.combined.detectionByScenario.H2.detection.runs] runs (the strike streak fires only once the buckets run dry) and its loss is still bounded by the daily limit (17.96 [r:results/x6_detection.json#byMode.combined.detectionByScenario.H2.maxLossBaseUnits/1000000] USDC at most). Detection is not containment.
- **At the pinned thresholds every on-chain freeze comes from the strike streak (T3), never the velocity tripwire (T1).** The burst bucket caps one hour below T1's trigger, so T1 can only fire at the tighter settings, which false-freeze legit bursts. The caps bound the loss; the strike streak and the watcher end the attack.
- **The watcher is what sees gas spam and approval spam**, neither of which breaches policy.
- **The recovery success path works end to end** and the hijack variants fail: two guardian keys never reach quorum, three are stopped by the owner's veto inside the window, and recovery never moves funds.

## Honest limits

- Counts over our own scripted scenarios and workloads: self-graded and synthetic. The scenarios and the workload schedules are in the repo so judges can add their own.
- Runs are on a local anvil chain with one-second blocks; watcher latency is one op (a poll after each op), not a network round trip.
- H4, H5 and H7 are outside the detection denominator by construction; read their containment, not a detection rate.
- The legit workloads are plausible-heavy but ours; a real owner with a bursty pattern needs the thresholds tuned on their own traffic (the sweep above shows the cost of each setting).
- The x402 facilitator is a local mock until the mainnet run (X3, user-run).
